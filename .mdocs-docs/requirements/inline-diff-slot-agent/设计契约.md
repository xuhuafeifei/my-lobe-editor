# Inline Diff × Slot Agent × mdocs — 设计契约

> **状态**：已同意（2026-10-27）— 用户确认「开始 coding」  
> 已落地的 `src/plugins/diff` demo 视为前置实验；本契约约束 API / flatten / overwrite_all(B) 补齐。

## 方案摘要

### 1. Live 树物化（已实验）

- 无第二棵树。`APPLY_DIFF_OP` 将 top-level block **替换/插入**为 `DiffHunkNode`。
- Hunk 子结构：`DiffChrome`（只读旧文预览）+ 可编辑正文（update/insert 为新文；delete 为旧文+红样式）。
- Keep：拆壳留正文（delete 则移除）；Undo：insert 删除 hunk，update/delete 用 `oldBlock` 还原。

### 2. Agent → 前端

```
Agent tool call
  → 服务端
  → SSE / 事件
  → 宿主前端
  → Lobe Slot API（md 入参）
  → Markdown DataSource → nodes → DiffHunk
```

### 3. 四 API

| API | 行为 |
|-----|------|
| `insert_after(slot, md)` | md→block(s)，在逻辑 slot 后插入 `kind=insert` hunk |
| `update_slot(slot, md)` | 目标块 → hunk(`update`, oldBlock=原 JSON) |
| `remove_slot(slot)` | → hunk(`delete`) |
| `overwrite_all(md)` | **做法 B**：新旧逻辑 blocks LCS → 批量 update/delete/insert hunk |

底层：Agent 只传 **md**；Lobe 负责 md→Lexical。

### 4. 双导出

| 名称 | 内容 | 用途 |
|------|------|------|
| **review draft** | live `exportJSON`（可含 `diff-hunk`） | 自动保存、崩溃恢复裁决 UI |
| **canonical** | flatten 后无 hunk 的正文 | 发布、只读端、给 Agent 的「当前正文」快照 |

- `hasPendingDiff()`：root 上存在 `diff-hunk` 即为 true。
- **发布**：`hasPendingDiff() === true` → **拦截**，提示先 Keep All / Undo All（或不逐条裁决完）。**不**做隐式 Keep All。

### 5. mdocs 职责

| 做 | 不做 |
|----|------|
| 存 review draft 与/或 canonical | 维护 base vs propose 双文档树 |
| 发布前门禁（调 Lobe `hasPendingDiff`） | 服务端物化 DiffHunk |
| SSE 把 tool 转成前端 API 调用 | |

### 6. Slot 规则

- **对外 slot = 逻辑序号**（相对 canonical 视图 / 约定 base 的 top-level 块），1-based。
- 物理 root 下标（含 hunk）**不对 Agent 暴露**。
- **已有 pending 时再 `overwrite_all`**（建议默认，待确认可改）：
  - **拒绝**并提示先裁决；或
  - 以 **Keep 视角 flatten** 为 LCS 旧侧再算（进阶）

本期契约默认：**有 pending 则拒绝 overwrite_all / 与 pending 冲突的 slot 写**，避免叠两轮提案。

### 7. overwrite_all（B）流水线

```
逻辑旧 blocks ← flatten(Keep 视角) 或「无 pending 的 live」
新 blocks ← md 解析
rows ← LCS（可复用 / 对齐 renderer computeLexicalDiffRows 的块级语义）
逐 row 物化 DiffHunk（equal 跳过）
自动保存 review draft
```

## 变更触达

## 风险与回滚

| 风险 | 缓解 |
|------|------|
| review JSON 发给无 DiffPlugin 的客户端 | 发布只出 canonical；只读端不加载 review |
| LCS 与 slot 漂移 | 逻辑 slot + 有 pending 时拒绝二次全文 |
| hunk 进 history 体积大 | `oldBlock` 必要；可后续压缩 |
| md 多块 vs 单 slot | `update_slot` 约定单顶层块；多块用 insert 序列或 overwrite |

## 测试要点

- 单 slot update/delete/insert → Keep/Undo
- review JSON round-trip 恢复 pending + UI
- `hasPendingDiff` 发布拦截
- `overwrite_all` 产生多 hunk，Keep All / Undo All
- 有 pending 时 overwrite_all 被拒绝（若采用默认）
