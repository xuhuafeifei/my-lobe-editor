# Inline Diff × Slot Agent × mdocs — 需求分析

> 一句话：Agent 通过 slot / 全文 API 改同一棵 Lobe live 树；改动物化为 DiffHunk；自动保存可带裁决态；发布禁止未决断。

## 背景

- 已在 `@fgbg/lobe-editor` 落地 **Inline Diff**：`DiffHunk` / `DiffChrome` 真节点挂在 live EditorState，hover Keep/Undo + 顶栏 Keep All / Undo All。
- 宿主（mdocs）侧原先倾向 base / propose 双文档 + 只读 `LexicalDiff`；现改为 **Lobe 单树裁决**，mdocs 不再维护平行 propose 树。
- Agent 改文走 **function tool → SSE → 前端调 Lobe API**（Lexical 在浏览器）。

## 目标

1. **对外四 API（Agent 友好，入参偏 md）**
   - `insert_after(slot, md)`
   - `update_slot(slot, md)`
   - `remove_slot(slot)`
   - `overwrite_all(md)` — 做法 **B**：md → blocks → 与逻辑 base LCS → 多个 DiffHunk
2. **持久化**
   - 自动保存：**review draft** = live JSON（可含 `diff-hunk`），意外退出可恢复裁决 UI
   - 发布：**canonical** only；**有 pending hunk 则拦截，不允许发布**
3. **mdocs 职责收敛**：存 draft（review 或 canonical）、文档元数据；不维护 base/propose 双渲染树
4. **slot 契约**：对外使用 **逻辑 slot**（相对 canonical / 约定 base），不用含 hunk 的物理下标

## 非目标（本期不做）

- 字符级 inline decorate 作为 Agent 主路径（可复用 renderer `computeLexicalDiffRows` 作 B 的块级 LCS）
- Agent 直连改 Lexical（必须经前端）
- 未决断状态下的「发布即隐式 Keep All」（明确拒绝；发布前必须裁决完）
- mdocs 服务端自己算 DiffHunk（算在 Lobe / 前端）

## 验收标准

- [ ] 四 API 可从 demo / 宿主调用；`update`/`insert`/`delete` 物化为 DiffHunk；Keep/Undo 行为与现 demo 一致
- [ ] `overwrite_all(md)` 走 LCS → 多 hunk，顶栏 N of M / Keep All 可用
- [ ] 导出 review JSON 再 `setDocument` 可恢复红绿与 pending
- [ ] `hasPendingDiff()`（或等价）为 true 时发布被拦截并提示
- [ ] 文档约定：逻辑 slot；有 pending 时下一轮全文 diff 的 base 规则写清并实现

## 依据

- 实现：`src/plugins/diff/`（DiffHunk / commands / ReactDiffPlugin）
- 只读对比（块 LCS 可复用）：`src/renderer/diff/compute.ts`
- 对话结论：Inline 真节点、review JSON 可恢复裁决、发布拦截未决断、overwrite 用做法 B
- 待确认：见设计契约「待确认」节
