# Markdown ↔ 颜色文本 双向 — 需求分析

> 一句话：让带文字色 / 背景色的内容能在 Markdown 与 lobe Lexical JSON 之间往返；本期默认做**行内文本色**，块级彩色区块另议。

## 背景

lobe 编辑器里颜色已存在：

- UI：`ColorPickerBtn` → `useEditorState` 对选区写 CSS（`color` / `background-color`）
- 存储：Lexical `TextNode.style` 字符串，例如 `color: #f00; background-color: #ff0`
- JSON：`SerializedTextNode.style` 字段已有

但 Markdown 链路**丢色**：

- **写出**：`CommonPlugin` 的 `registerMarkdownWriter('text')` 只处理 bold/italic/strike/underline/sup/sub，**不读 `node.getStyle()`**
- **读入**：`mdReader` 的 `html` reader 只认 `<ins>`/`<u>`/`<em>`/`<strong>`，**不认带 style 的 `<span>`**
- 解析侧已有 HTML 标签栈（`parse.ts`），和现有 `<ins>` 下划线同模式，扩展成本可控
- `remark` 格式化会保留 `<span style="...">...</span>`（已本地验证）

## 目标

1. MD → Lexical：带约定语法的彩色文本解析为 `TextNode`，`style` 写入对应 CSS
2. Lexical → MD：带 `color` / `background-color` 的 `TextNode` 写出为约定语法
3. 与现有 **粗体 / 斜体等 format** 可叠加（例如红 + 粗）
4. 往返尽量稳定（同色同文再导入不丢）

## 非目标（本期不做，除非另选）

- 块级「彩色 callout / 色块容器」新节点（与行内 TextNode.style 不同）
- 任意 CSS（只白名单 `color` / `background-color`）
- 改 mdocs 服务端独立 markdown 管线（若 mdocs 自有 `markdown-to-lexical`，另开变更触达）

**倾向**：S1 + C1 + B1。

## 验收标准

- [ ] MD 含彩色 span → `getDocument('json')` 中对应 text 节点有正确 `style`
- [ ] 编辑器内设色 → `getDocument('markdown')` 含对应 span
- [ ] 往返一轮后颜色仍在；无色文本不额外包 span
- [ ] 与 `**bold**` 等组合不互相抹掉
