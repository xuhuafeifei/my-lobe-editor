# 文件上传增强（zip / 音频）— 需求分析

> 一句话：在现有 Upload + File 体系上，明确支持 zip 与音乐文件的上传与呈现；本期不做解压预览，音频是否内嵌播放器待确认。

## 背景

编辑器已有：

- `UploadPlugin` + `IUploadService`：拖拽 / 粘贴的优先级 handler 链（见 `map/plugins.md`、`src/plugins/upload/service/i-upload-service.ts`）
- `FilePlugin` + `FileNode`：通用附件节点（名称 + URL + pending/uploaded/error），UI 用 `MaterialFileTypeIcon` 按文件名出图标

文档里已示例「按 mime 注册 audio handler」，但库内**没有**独立 Audio 节点，也**没有**对 zip/audio 的显式 allowlist。\
`FilePlugin` 当前注册的 upload handler **不按类型过滤**，且返回 `null`（不认领），与 `UploadService`「第一个返回 truthy 即成功」的约定不完全对齐 —— 扩展类型支持时应一并理清。

## 目标

1. **zip**：可作为附件上传并插入文档（拖拽 / 粘贴 / 命令），Markdown 导出为链接形式（与现有 File 一致）。
2. **音乐 / 音频**（常见：`mp3` / `wav` / `m4a` / `ogg` / `flac` 等）：可上传并插入；呈现方式见下方分叉。
3. 通过 **mime / 扩展名 allowlist** 控制哪些文件走 File（或 Audio）路径，避免误吃图片等已有专用插件处理的类型。
4. 上传实现仍由宿主提供 `handleUpload`（库不自建存储后端）。

## 非目标（本期不做）

- zip **解压、列目录、预览内部文件**
- 服务端病毒扫描 / 配额策略（宿主职责）
- 视频节点
- 改 ChatInput 附件栏产品交互（除非验收要求点入口）

## 已确认（2026-07-31）

| #   | 决策                                     |
| --- | ---------------------------------------- |
| A   | **A1** `FileNode` 附件卡片，不内嵌播放器 |
| B   | **B1** zip 普通 File 卡片                |
| C   | **C1** 可选 allowlist；未配置不限制      |
| UX  | 上传成功后**可下载**即可                 |

## 验收标准

- [ ] 拖入 / 粘贴 `.zip` 可插入附件节点，上传成功后有可访问 URL（宿主 mock 即可）
- [ ] 拖入 / 粘贴约定音频扩展名可插入（按所选 A1/A2 呈现）
- [ ] 图片等已有插件类型行为不回退
- [ ] Markdown 写出含文件名与 URL
- [ ] 不在 allowlist 内的类型：可配置拒绝或走现有兜底（与 C 一致）
