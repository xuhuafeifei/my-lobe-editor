# 文件上传增强（zip / 音频）— 设计契约

> **状态**：已同意（2026-07-31）\
> 用户确认：附件卡片即可，需支持下载；不要求内嵌播放器。

## 方案摘要

1. **zip / 音频均作为 `FileNode` 附件**（A1 + B1）。
2. **附件卡片可下载**：上传成功后点击卡片（或文件名）触发下载 / 打开 URL。
3. **`FilePluginOptions` 增加可选 allowlist**（C1）：
   - `allowedMimeTypes?: string[]`（支持前缀如 `audio/`）
   - `allowedExtensions?: string[]`（如 `zip` `mp3` …）
   - **未配置 = 不限制**（兼容现有「任意附件」用法）。
4. **Upload handler 返回值**：认领返回 `true`，不匹配返回 `false`。
5. **Image 非图片早退**：upload handler 对非 `image/*` 直接 `false`，避免 zip / 音频先走图片读宽。
6. **不做**：zip 解压、内嵌 `<audio>`、视频节点。

## 风险与回滚

| 风险                            | 缓解                                                     |
| ------------------------------- | -------------------------------------------------------- |
| 跨域 URL 的 `download` 属性失效 | 同时 `target="_blank"`，至少可打开后另存                 |
| File 认领过宽                   | 宿主可配 allowlist                                       |
| Image 早退影响无 MIME 的图片    | 仅 `!image/*` 早退；无 MIME 仍进 Image 再由 command 判断 |
